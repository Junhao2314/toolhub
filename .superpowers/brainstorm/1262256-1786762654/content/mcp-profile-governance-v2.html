MCP / Profile 治理

一个共享运行时、按会话精简工具、调用时统一执行风险策略。

控制面实时数据面外部运行时

ToolHub

  • Profile、版本和 Secret bindings
  • MCP 配置与工具定义变更审查
  • 工具可见性与全局风险上限
  • Apply、自动检查与修复、回滚
  • 30 天五分钟聚合统计
应用配置不参与实时调用

mcpm 共享 relay

  • 每个 MCP 上游只启动一个实例
  • 会话打开时绑定 Profile revision
  • tools/list 只返回本 Profile 可见工具
  • tools/call 执行 allow / confirm / deny
  • 24 小时无载荷调用元数据
复用进程并发请求

MCP 上游集合

  • acemcp、搜索、浏览器及其他服务
  • Profile 隐藏工具不停止进程
  • 开多个 Claude/Codex 不增加实例
  • Hermes 不进入新 Profile routing
  • 超时后高风险调用绝不自动重试

ToolHub 故障不阻断已运行的 MCP 调用relay 使用最后一次成功应用的本地快照

一次调用如何被处理

客户端只提交稳定 Profile ID；revision 在连接时固定。

实时路径

1. 会话绑定

  1. Claude/Codex 连接 relay
  2. 合法 Profile ID → 绑定当前 revision
  3. 未选择 → 使用明确配置的默认 Profile
  4. 无默认 → 不显示任何工具
  5. 无效或已归档 → 拒绝，不静默回退

2. 工具列表与调用

  1. 工具列表：accepted baseline ∩ Profile visibility
  2. 风险决策：全局 ceiling 先执行，Profile 只能收紧
  3. 新工具默认隐藏，schema 变化的工具暂停
  4. 缺失可信 annotation 默认需要确认
  5. 参数只在内存中做 canonical SHA-256

3. 高风险确认

  1. 绑定 Profile revision
  2. 绑定 MCP config revision
  3. 绑定 Contract revision 与精确工具
  4. 绑定参数哈希，消费后才 dispatch
  5. 超时显示“执行结果未知”，检查后重新确认

三个版本互不混用

配置、观察到的工具定义和用户工作配置分别审计。

不可变版本

MCP Config Revision

server launch

命令、URL、transport、Secret slots 等启动配置。编辑先产生未启用版本，经共享 relay 一键更新后生效。

Observed Contract Revision

tools schema

实际观察到的工具名称、输入/输出 schema、annotation 和描述。accepted baseline 只通过人工审查推进。

Profile Revision

task config

精确 Skill/MCP pins、工具可见性和风险收紧规则。relay 更新会为受影响的非归档 Profile 创建新 revision。

工具定义变化

“疑似改名”只提示，不自动继承。

需审查
发现的变化立即行为用户操作
仅描述变化继续可用显示提示，可单项或按服务器接受
新增工具暂时隐藏审查 schema 和风险后显式接受
schema / annotation 变化暂停该工具接受新 baseline 或明确保持暂停
工具移除不可用Profile 保留历史引用，UI 显示缺失
相同 schema 的增删对疑似改名新工具仍隐藏；一键确认后继承可见性和风险策略

配置操作顺序

保存 Profile→应用前检查→应用配置→启动会话
  • “复制启动命令”只在应用成功后作为辅助入口
  • Skills 完整替换可管理范围；自动检查与修复只修 pinned 成员
  • 共享 relay 更新先预览影响并支持失败回滚

可观测但不记录内容

  • mcpm：24 小时调用时间、状态、延迟、工具和 revision IDs
  • ToolHub：30 天五分钟聚合，显示使用量、失败和 fallback 无关健康
  • 永不保存参数、结果、prompt、原始错误、请求/响应或持久会话 ID
  • 中文主界面使用“工具定义已变化”“自动检查与修复”等通俗词

本节需要确认：ToolHub 只做控制面；mcpm relay 独立执行实时工具列表、风险确认和调用。Profile 选择不启动或停止 MCP 进程。
