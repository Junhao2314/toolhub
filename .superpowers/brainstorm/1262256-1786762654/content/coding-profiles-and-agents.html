职责边界与调用路径

ToolHub 是 control plane；Claude、Codex 和 mcpm 分别执行原生职责。

推荐架构

ToolHub 控制面

  • Profile 与不可变配置版本
  • Agent preset 与原生配置生成
  • 工具可见性、风险策略和定义变更审查
  • Apply、回滚、健康与无载荷聚合统计

Claude / Codex 主会话

  • 启动时选择稳定 Profile ID
  • 绑定当时的 Profile revision
  • 主模型负责宏观规划和最终判断
  • 原生线程界面展示子代理状态

客户端原生子代理

  • 同一主模型，reasoning = medium
  • 读任务可并行
  • 同一工作区最多一个 writer
  • Claude writer 可选 worktree 隔离
生成并 Apply 原生配置 →原生 dispatch / review →

mcpm 共享 relay

  • 所有 MCP 上游各运行一个实例
  • 按 Profile revision 返回精简后的 tools/list
  • 统一拦截 allow / confirm / deny
  • 高风险调用不自动重试

MCP 上游进程集合

  • acemcp、搜索、浏览器及其他服务始终运行
  • 开多个 Claude/Codex 不增加 MCP 进程
  • ToolHub 不在同步调用路径上
  • 只持久化无参数、无结果的运行元数据
明确不做：ToolHub 不创建通用 Agent runtime，不接管任务队列、对话、prompt、transcript 或 token 内容，也不替代 Claude/Codex 的原生权限与线程管理。

交互原型，仅用于确认信息架构与职责边界；不代表已经实现。
